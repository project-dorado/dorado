## Phase E — Severity-ranked findings

### High
- **H-1 · CD rip/burn report success while writing nothing.** `CDViewModel.cs:150-202`
  loops on `Task.Delay` and displays "Ripping complete. Media cataloged into
  collection." / "Burn complete. Closing disc session." with no output files and
  no cataloging. Impact: misleading user-facing status. (Disclosed as simulated
  in README, but the *runtime messaging* asserts success.)
- **H-2 · Device Info is fabricated.** `SettingsViewModel.cs:1261-1271` hardcodes
  "Zune HD (Simulated Standby)", serial `0001020304050607`, firmware
  `v4.5 (3084)`, battery `88% (Charging)`, capacity `32 GB` — even when a real
  device is connected; capacity also feeds space-reservation math.
- **H-3 · DISC pivot is permanently visible.** `CDViewModel.cs:104-130` seeds an
  8-track sample disc at construction, so `MainShellViewModel.cs:49` `HasDisc`
  is always true and the pivot button (`MainShellView.axaml:171`) never hides —
  contradicting the Phase B "DISC made ephemeral" intent.

### Medium
- **M-1 · Mosaic wall is not album art.** `NowPlayingView.axaml:282-318` renders a
  `MusicNote` placeholder + title per tile; no `ArtworkUri` image binding. The
  README claims "3D/2D grid of collection album covers".
- **M-2 · No per-mode cross-fade in Now Playing.** Mode switches are plain
  `IsVisible` toggles (`NowPlayingView.axaml:19,282,360`); only the shell
  transition animates.
- **M-3 · NP transport hover/pressed variants are dead.** `_isNowPlayingButtonHovered`
  /`_isNowPlayingButtonPressed` (`MainShellViewModel.cs:148-165`) are never read;
  `NowPlayingIconTests.cs:26` locks in the no-op behaviour, yet Top-15 #3 is
  marked closed.
- **M-4 · Smart DJ has no timeout or progress callback.** `SmartDJEngine.cs:20-71`
  is synchronous; no `IQuickMixProgress`. Top-15 #7/#11 remain open.
- **M-5 · Playlist search absent.** `CollectionViewModel.cs:551-594` and
  `MainShellViewModel.cs:245-301` cover songs/albums/artists + podcasts/videos
  only. `CollectionViewModel.PerformSearchAsync` (`:672-680`) is dead code.
- **M-6 · Documentation drift.** Mini-player size (README 480×110; two audits
  420×130; code 340×96); FFT interval (75 vs 33 ms); README pivot list omits
  shipped DISC/SOCIAL; README "Known internal bugs" still lists the *fixed*
  pivot-gating bug; GEMINI omits `Dorado.Infrastructure.Video`.

### Low
- **L-1 · Dead code:** `CollectionViewModel.PerformSearchAsync`; redundant
  `PodcastsViewModel` DataTemplate (`MainShellView.axaml:34-36`).
- **L-2 · Registry overclaim:** `gap_inventory.md:715` summary counts closed items
  that are partial/open (see D.1).
- **L-3 · DSP prior silently substitutes.** `AudioAnalysisService.cs:83-90,134`:
  when there are no favorites (or no decodable file) the metadata prior runs, so
  "real DSP" is conditional — worth stating in the README.
- **L-4 · WAV tags absent** → `Unknown Artist/Album` (acceptable fallback).
- **L-5 · Gallery label.** The mini-player capture was re-rendered at the correct
  **340×96**; the earlier mislabel was corrected before commit.

### Confirmed strengths (re-verified independently)
- Build/test/design gates all green; **real BASS playback** verified
  non-simulated; **real DSP** wired (`DspFeatureExtractor` via `BassPcmDecoder`).
- FTS5 external-content index with triggers + bm25 + LIKE fallback.
- 10-band EQ (8 presets); plugin host with complete host services and `.znp`
  packaging; Last.fm + Discord reference plugins; 6×3 badge taxonomy; both
  wizards; 8-zone resize; runtime dark/light theme swap.
- No `TODO`/`FIXME`/`HACK`/`NotImplementedException` in `Dorado.UI` or
  `Dorado.Desktop`; no orphaned views; no Microsoft binary content bundled.
